Enter and save eight customer records: name, email, and a follow-up note. Compare RobotJS and Rusty Robot after accounting for how they pace typing.

Correction: the earlier default-settings video showed a large Rust advantage because RobotJS waits between characters while Rust batches text. That was not an apples-to-apples typing-rate comparison. The results below use explicit settings and repeated runs.

Both libraries receive the same data and must save every field correctly. Each condition has one warmup and six measured runs per library, with execution order reversed every round. Video capture is off during measurements.

1. Request zero keyboard delay

Both APIs use keyboard delay 0 ms and mouse delay 10 ms. This compares their normal text-entry APIs with configurable keyboard pacing disabled. Rust still has an internal 10 ms safety floor between text batches; RobotJS sends per-character events. The implementations are different, but the requested task, settings, and required result match.

Both use their explicit paced-typing API at 6,000 characters per minute (100 per second). Mouse delay is 10 ms; key-tap delay is 0 ms. This removes the default per-character versus per-batch pacing difference.

What this tells us

The earlier default-settings gap does not survive controlled pacing. These results describe the complete form task on one Mac, including OS delivery, app updates, and verification. They do not isolate language execution speed or establish a general winner for desktop automation.

The app is a purpose-built browser test fixture, using synthetic customer data. Mouse and keyboard events go through the real native APIs. The harness reads the app to check delivery; it does not inject form values or click events through JavaScript. The run stops if the owned window loses focus.

We could not establish a working RobotJS capture baseline in this session. The earlier capture failure is excluded from the speed comparison. The failure log remains available.

Method, source, and all runs

Apple M6, macOS 27.0, Node 24.22.0. RobotJS is pinned to the recorded source revision; Rusty Robot uses 0.1.3 library code. Each run starts with a fresh driver process and a reset app. Startup/reset are outside the timer. The timer begins before the initial native click and ends when the app has received and verified the eighth submitted record. Read-only checks and local control IPC are included.

The paced condition controls the requested character rate; native event delivery and scheduling still add overhead. Six trials and their ranges are descriptive, not confidence intervals. The recorded illustrations are additional runs, not selected fastest samples. Videos are silent; text results appear in the page.
