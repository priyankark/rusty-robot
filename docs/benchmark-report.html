Rusty Robot vs RobotJS

Same kinds of work. Two implementations. See where the Rust port saved time—and where RobotJS was faster.

Both libraries let programs control the mouse and keyboard, capture the screen, and search images. RobotJS exposes native C/C++ code to Node.js. Rusty Robot reimplements the library in Rust and calls the operating system directly. It does not run the RobotJS addon internally.

How to read this: choose a workload, then compare the two bars for each operation. Hover or tap its name to see exactly what it does. Shorter is faster.

Rust had lower medians in 17 of 21 cases, including near-ties. There is no single overall speedup. These are API timings; typing, clicking, and entire app workflows were not timed here.

What the numbers include

Three rounds, seven adaptive batches per process, warmed caches, release builds, and alternating implementation order. A median is the middle value after sorting the 21 batch averages. It is not the slowest call or a guarantee for your application.

Returning thousands of positions includes allocation: Rust vectors and JavaScript objects have different costs. BMP loads and saves use different buffer/file formats. File writes do not include forcing the data to durable storage. The case explanations flag these differences.

The capture timings use the October 27 Rust implementation. Capture improved afterward, but the latest path has not been rerun against RobotJS. Read what changed.

Environment and reproduction

Apple M6, macOS 27.0, Node 24.22.0, Rust 1.99.1. RobotJS 0.9.1 at revision 0af6073e1f1bcff865ffe52801c71647829cdc1c, built with node-gyp Release and PNG enabled. Rust uses the default release profile.
