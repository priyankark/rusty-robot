Rusty Robot vs RobotJS

The complete measured comparison: bitmap access, color and image search, image codecs, cursor queries, display enumeration, and screen capture. Current optimized Rust versus RobotJS 0.9.1’s JavaScript API and native C/C++ addon, on an Apple M6 Mac.

Bitmap access & search

In-memory pixel reads are 15.65× faster. Late and absent exact color searches are about 2.1× faster. Exact image search is roughly tied; tolerant image search is 1.17× faster. Returning 65,536 color matches is 267× faster, including the difference between Rust vectors and JavaScript object allocation.

Image loading & saving

BMP loading takes Rust 1.13× as long; PNG loading is 1.17× faster. BMP saving is 1.19× faster by median, with substantial RobotJS variation between rounds. PNG saving is essentially tied. BMP storage formats and PNG output sizes differ between APIs.

Desktop queries & capture

Cursor position queries are 3.85× faster, but display enumeration takes 1.27× as long. Single-pixel and 100×100 captures take Rust 6.08× and 5.43× as long. Full-screen capture is broadly comparable; overlapping round ranges make the 1.12× median advantage uncertain.

What this report covers

All 21 measured operations, including unchanged paths and slowdowns. This is a performance comparison, not a complete feature-parity audit. Keyboard typing, mouse movement/click delivery, and end-to-end automation throughput were not benchmarked. Native desktop measurements cover macOS only.

What changed

Exact color searches use packed RGB comparisons, ignoring alpha. Image searches check needle pixels backwards. BMP loading copies compatible rows; saving assembles a single payload for bulk writing. Output formats and match ordering are preserved.

Tradeoffs & remaining gaps

Compared with the previous Rust build, tolerant image search measured about 2.7% slower; it remains faster than RobotJS. BMP saving needs an extra output-sized buffer (6.22 MB here). Small screen captures remain substantially slower than RobotJS; their native backend was not changed.

How to read the results

Speedup = baseline time ÷ optimized Rust time. Above 1× favors optimized Rust. RobotJS uses a native C/C++ addon, not pure JavaScript. Exact image search is roughly tied with RobotJS. Dense result collection includes Vec versus JavaScript object allocation. BMP formats differ between APIs.

Measurement & verification

Three rounds × seven timed batches, warmed caches, release builds, sequential execution and alternating order. All 126 Rust/RobotJS and 78 Rust before/after process measurements passed. Headless tests and lint passed; 36 opt-in desktop tests were not rerun for these bitmap changes. Native Linux/Windows verification remains outstanding.

Environment and reproducibility

Timings are median batch averages, not tail latencies. Synthetic fixtures do not represent every screenshot. File writes exclude fsync. Rust BMP loads produce BGRA32 versus RobotJS BGR24; saves use BMP24 versus BMP32. RobotJS BMP saving varied from 1.080–2.181 ms across rounds. PNG and native desktop code were unchanged.
