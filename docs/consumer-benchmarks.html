AirCodum inside an actual VS Code extension host, and Agentum's actual VNC server. Rust handles input, capture, resize, frame hashing and JPEG/PNG encoding through bounded workers. The original app paths use RobotJS for input and native macOS subprocess capture/resize for video.

21-operation RobotJS API comparison · Source & agent skill · Method and raw evidence

Three independent runs per backend, alternating order. Video: 1440×810, JPEG quality 85, target 30 FPS, adaptation disabled, ten seconds each of owned static and 30 Hz motion content. Results describe this Mac and loopback transport; they are not an internet/mobile latency claim. Nominal quality numbers do not guarantee identical encoder fidelity.

Measurement boundaries and remaining work

Video measures capture through resize/encode, authenticated WebSocket transport and receipt of JPEG bytes. The first and last frames are decoded after timing; every frame's dimensions and motion changes are checked. It does not measure rendering on a remote phone. Ping RTT measures control responsiveness while video runs.

CPU is the Node/extension-host process, including Rust worker threads and benchmark bookkeeping. It excludes the original path's screencapture/sips subprocesses, WindowServer, VS Code renderer and stimulus. These CPU numbers cannot establish total energy or system-CPU savings.

Static frame rate is intentionally low because unchanged frames are suppressed. Motion delivered FPS and inter-frame gaps are the throughput metrics. JPEG file sizes and quality differ by encoder. No composite “overall speedup” mixes unrelated operations.

Rust's one-shot ScreenCaptureKit capture still limits sustained video below the requested 30 FPS. A persistent capture stream, dirty-region transport and remote-display latency tests remain future work. This is a validated preview, not a finished VNC product.

Agentum input measurements isolate input by stubbing the unrelated capture subscription. Its video measurements use the real capture and server. AirCodum input runs through real VS Code; video is stopped for isolated input measurements. Failed original Unicode/multiline deliveries are correctness failures and receive no speedup ratio.
