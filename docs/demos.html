Recording and verification details

Each implementation runs separately in the same owned Chrome test app on an Apple M6 Mac, macOS 27.0. The recordings are aligned at the task start and combined side by side at original speed; the finished pane holds its final frame. Synthetic customer data uses example.test addresses. There is no audio; results appear in the video and above.

Mouse and keyboard actions go through the libraries’ native OS APIs. The recorder reads app state to check that text and clicks arrived; it does not insert the form values or dispatch synthetic input. Input stops if the owned window loses focus. Target coordinates come from each library’s screen capture and color search, not the page’s target coordinates.

These are demonstrations of complete tasks, not repeated isolated latency measurements. The 21-operation report uses a separate, dated experiment. The capture failure here does not change those historical samples.
