15.5× faster on this workload.

Find every green “Ready” badge across 60 dashboard screenshots, then return its bounding box. Rusty Robot did the search and grouping in 49.3 ms; RobotJS from Node took 763.9 ms.

These are medians from six runs per library, in alternating order. All 12 runs returned the exact same 1,527 rectangles. The screenshots are generated test dashboards with 2,400 order cards—not a production customer workload.

What is timed: search every image for the known badge color, collect matching pixel positions, and group them into rectangles. Both use their public find-all-color APIs and the same grouping steps.

Outside the timer: screenshot capture, PNG decoding, disk reads, and a full warmup. Both receive identical, preloaded BGRA32 buffers. This measures image analysis, not complete desktop automation latency.

Why this favors Rust

The find-all-color call returns many matching pixel positions. RobotJS creates JavaScript objects for those results; Rust returns a vector. The grouping loop also runs in JavaScript versus compiled Rust. Both perform the same algorithm on the same pixels. These timings include the public API’s result-allocation costs, which are part of this workflow.

This is color-based detection for a known UI, not OCR or a general vision model. It does not establish a universal Rust advantage or compare every possible custom JavaScript implementation. In our controlled form-entry comparison, RobotJS was faster with zero keyboard delay, and matched-rate typing was effectively tied.

Reproduce it and inspect the evidence

Apple M6, macOS 27.0, Node 24.22.0, Rust release build. Each process loads the same 60 images, validates a complete warmup, waits for the start signal, and processes the batch. Output checks run after the timer. Library order reverses each round. The 60 images are distinct pages of one generated dashboard design, so this is a narrow workload, not a diverse screenshot corpus.

The checked-in PNG archive and fixture metadata preserve the exact inputs and expected rectangles. The archived byte-buffer hashes allow decoded inputs to be checked before running. No typing delays or artificial sleeps enter the timed analysis.
